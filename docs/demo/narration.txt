Clearance helps teams decide how much freedom an agent's change has earned. Each change becomes a flight, with its risk, verification and outcome visible in one place.

A person starts with an intent issue. The Dispatch workflow plans the change, asks the governor for a predicted clearance, implements it with tests, and routes the result to an independent Inspector. The final recording will show this work in a real GitLab Duo session.

The governor is deterministic code. It combines eight change-risk signals with the pilot's track record and the service's error budget. Verification follows risk, so a small change can take a lean path while a core rewrite receives broader checks. Security scanning remains in the pipeline.

New agents begin supervised. A human approves the outcome while the pilot builds a real record of successful flights. Once its measured trust and the change risk permit it, the autonomous path can request an automatic merge. The submission's chosen autonomy level must match the run shown here.

After release, progressive delivery compares the canary with the stable revision. Error rates, latency and SLO burn determine whether traffic advances. In a controlled failure run, the system rolls traffic back and opens an incident. The pilot's trust then reflects that outcome.

The same governor holds changes to the rules that govern agents. This boundary stays visible in the merge request explanation and the evidence trail.

Every flight can leave a hash-chained evidence pack, a trust-ledger update and a Software Carbon Intensity report. The carbon calculation models energy using public coefficients; it must label estimated durations and exclude unmeasured inference and browser rendering costs.

The current local rehearsal verifies these engine and CLI paths against a mock GitLab API and deterministic canary probes. It is development evidence, not a real Duo run or Cloud Run deployment. Clearance makes delivery decisions inspectable, autonomy bounded, and failure reversible.
